# 任务成就报表设计（成就页）

> 对应 README 路线图 P2「任务统计报表」。
> 2026-11-11 改版：由「统计」页升级为「成就」页，理念从"记录数据"改为
> "它替你做了什么、效率是多少"，新增效率口径与 7 日双线折线趋势。
> 视觉沿用 docs/ui-redesign.md + design-system/default/MASTER.md，不新建设计系统。

## 1. 目标与范围

- 回答两个问题：**帮助用户做了什么**（累计轮次 / 战斗 / 运行时长）、
  **效率是多少**（每小时完成量）。
- 入口：侧边栏「成 就」，位置在「设置」后「系统」前，常显（不受组号/诊断
  条件显隐影响）。
- 页面组成：**当前角色标识 → 四张 KPI 卡 → 最近 7 天折线趋势 → 按任务模式
  明细表 → 清空记录**。
- **按角色隔离**：成就存 `data/<角色ID>/task_stats.json`，切换账号各自
  一份；旧版全局数据迁移时归当前绑定角色（docs/user-data-layout.md）。
- 数据累计持久化：跨任务会话、跨天保留；与看板"本次运行"状态严格区分
  （看板读会话级状态文件、任务结束即删；成就是历史档案）。
- 本版不做：节省时间估算、并发多实例设置隔离、30 天窗口、导出/筛选、
  日级效率趋势线。

## 2. 信息架构

侧边栏顺序（现有：运行 / 任务 / 组号? / 设置 / 系统 / 诊断?）：

```
运行 / 任务 / 组号? / 设置 / 成就 / 系统 / 诊断?
```

- 入口样式沿用 `.nav-item`：内联 SVG（1.5px 描边、17px）+ 两字文案「成 就」。
- 图标用 lucide trophy 奖杯（语义贴"成就"），与既有图标同风格同尺寸。
- 内部标识保持不变：`data-page="stats"`、`switchPage('stats')`、
  `get_task_stats` / `clear_task_stats`——只改用户可见文案，避免无意义 diff。

### 3.1 KPI 四卡

- **累计轮次 / 累计战斗 / 累计运行 / 平均效率**，纯数字，无仪表盘。
- 前三张副行「今日 +N」（今日取**真正的今天日期键**，今天没跑显示 +0，
  不取"最后一个有数据的天"）；效率卡副行「近 7 日 X 轮/时」。
- 效率口径：
  - 全局效率 = 累计轮次 ÷ (累计运行秒数 ÷ 3600)，保留 1 位小数；
    **分母包含仅战斗时间**，与「累计运行」卡可互相推算。
  - 近 7 日效率 = 7 天轮次和 ÷ 7 天运行小时和。
  - 样本不足 60 秒显示「—」（防 1 分钟跑出三位数速率）。
- 数字 ≥1000 加千分位；耗时沿用 `d/h/m` 自适应格式。
- 不展示「本次会话」条——实时状态由运行看板承担，避免两页重复。

### 3.2 最近 7 天趋势

- **固定最近 7 个自然日（含今天）**，无数据日补 0；横轴标签短格式 `M/D`，
  今天的标签用 accent 色强调。
- **双线折线**：轮次 = `--accent`（竹青），战斗 = `--gold`（鎏金）；
  同一纵轴（同为"次"）。不画耗时（量纲不同，双轴易误读）、不画效率
  （日粒度小样本尖峰）。
- 纵轴 0 起点，4 档刻度（0 / 1/3 / 2/3 / 上限），上限取
  1/2/2.5/5/10 × 10^n 的整洁值；折线为直线段，不做平滑过拟合。
- 每个自然日一列透明命中区，悬停显示「日期 · 轮次 N · 战斗 M」
  （SVG `<title>`，零依赖）。
- 图下一行文字摘要（a11y 兜底）：
  「7 天合计 轮次 X · 战斗 Y ｜ 日均 Z 轮 ｜ 最高 MM-DD（N 轮）」；
  日均 = 7 天总量 ÷ 7（没跑的日子按 0 摊）；并列最高取最近一天。
- 7 天全为 0 时图区显示「最近 7 天没有运行」，KPI 与明细照常。
- 实现：**内联 SVG 手绘**，不引图表库（离线桌面应用，保持 pywebview
  纯 HTML/CSS 零依赖）；按容器实际宽度计算坐标，窗口缩放 150ms 防抖重绘，
  页面无水平滚动。

### 3.3 按任务模式明细表

- 五列：**模式 / 轮次 / 战斗 / 效率 / 耗时**。
- 效率 = 该模式轮次 ÷ 该模式运行小时，显示 `28.5/h`；仅战斗行轮次显示
  「—」、效率按战斗场次计算；样本不足 60 秒显示「—」。
- 行序固定 `_STATS_MODES` 顺序（页面每 1.5s 刷新，按轮次排序会让行在运行中
  来回跳）；零数据行保留置灰。
- 右上「累计｜今日」分段 chip 切换，默认累计；今日视图同样按今天的日期键取数。
- 任务运行中当前模式行高亮（`--progress-tint` 底 + 左侧 `--accent` 竖条），
  累计/今日两视图都保留。
- 表下一行口径说明：「效率 = 每小时完成轮次；仅战斗按场次计算。」

### 3.4 清空记录

- 「清空记录」link-btn（`--danger` 悬停态），二击确认（3s 内再点一次），
  任务运行中禁用（与"运行中不可修改"全局语义一致，防与子进程写文件竞态）。

## 4. 关键交互规格

| 交互 | 规格 |
|------|------|
| 进入成就页 | `switchPage('stats')` 立即刷新一次 |
| 页面内刷新 | 页面激活期间 1.5s 轮询（与看板同节拍）；数据 JSON 签名比对，无变化不重渲染 |
| 窗口缩放 | 页面激活时按新宽度重绘趋势图（150ms 防抖） |
| 离开页面 | 停止轮询（switchPage / pollStatusTick 既有钩子） |
| 累计/今日切换 | 即时，无请求（数据一次取回，前端切视图） |
| 清空记录 | 二击确认；运行中禁用；清空后立即刷新为空态 |
| 数值更新 | 150–200ms 过渡；`prefers-reduced-motion` 下直跳（全局规则） |
| 键盘 | 全部可 Tab 到达，focus-visible 2px accent outline（全局已有） |

## 5. 后端数据通道（按角色隔离）

### 5.1 数据模型：data/<角色ID>/task_stats.json

- 文件路径 `data/<角色ID>/task_stats.json`（2026-11-11 起按角色隔离；
  角色取窗口标题「（ID：数字）」，无 ID 退 `_default`）。
  **与状态文件分家**：状态文件会话级、shutdown 删除；统计文件是历史档案。
- 旧版根目录 `task_stats.json` 在升级迁移时复制给当前绑定角色，原文件
  保留用于回滚；迁移细节见 docs/user-data-layout.md。
- **单写者 = 任务子进程**（复用 debug_overlay._supervise 既有 2s 周期，
  同一循环内原子写入；shutdown() 里删状态文件前先终写一次统计）。
  主进程退出时 `atexit` 也会写一次，但只写 session 快照、不计累计。
- 结构（不变）：

```json
{
  "total": {"rounds": 128, "battles": 347, "seconds": 94320,
            "modes": {"修罗": {"rounds": 48, "battles": 210, "seconds": 34320}}},
  "daily": {"2026-11-06": {"rounds": 22, "battles": 65, "seconds": 19800,
                           "modes": {"修罗": {"rounds": 10, "battles": 30, "seconds": 9000}}}},
  "session": {"started_at": 1762600000, "rounds": 5, "battles": 18,
              "seconds": 2460, "mode": "修罗"}
}
```

- `daily` 滚动保留最近 90 天（写时修剪），防文件无限增长。
- 效率、7 日补零、日均全部在前端由 `total` / `daily` 派生，后端不打新点。

### 5.2 打点（既有，不改）

| 指标 | 打点方式 |
|------|----------|
| 轮次 | 各任务模块每轮完成点调 `debug_overlay.record_round()`（kezhan/wubei/wuhuan/xiuluo/xuanshu/mingwang） |
| 战斗 | 复用 `set_battle(no)`，supervisor 每周期对比上次序号求增量，归当前模式 |
| 耗时 | supervisor 每周期把 tick 增量归当前模式 + 当日 |
| 会话 | `start()` 置会话开始时间；session 快照随 tick 写入（页面不再展示） |

当前模式不是单一有效模式（启动期多模式串「修罗、五倍」）时只计总数不计模式。

### 5.3 桥接接口（control_window.py，不改）

| 接口 | 行为 |
|------|------|
| `get_task_stats()` | 读当前角色 `data/<ID>/task_stats.json` → 返回 `{total, daily(最近 7 个有数据的天), session, role{id,label}}`；文件缺失/损坏返回空结构 |
| `clear_task_stats()` | 任务运行中拒绝；否则删除当前角色的统计文件，返回 success |

### 5.4 已知边界：多实例

- 一个程序实例内只有一个任务进程（`TaskManager._busy` 守卫）；「组号」是单进程
  串行切换 Tab，不产生并发写。
- 成就/方案/进度/高性能缓存已按角色分文件；两个程序副本绑定不同角色时
  这些数据互不覆盖。
- 但 `config.json` 仍是共享的当前设置快照，**并发多实例（同时运行）**
  仍受前台输入模型限制，不在本版范围；单实例切换账号时角色数据自动
  跟随实际游戏窗口（绑定窗口关闭后打开其他窗口会改绑并刷新面板，
  2026-11-13），启动时按角色方案整体切换。若后续支持并发多角色，再把
  当前设置也按角色彻底拆分。

## 6. 视觉沿用（不新建设计系统）

- 全部沿用 ui-redesign 语义 token 与 MASTER.md（深色墨色 / 浅色宣纸双主题
  自动适配）；折线色 = `--accent`（轮次）与 `--gold`（战斗），网格 `--border`，
  轴文字 `--text-dim`。
- 图标：内联 SVG 1.5px 描边，禁 emoji；圆角卡 8px；间距 4/8px 节奏，
  页面 padding 14px。
- 动效 Subtle 档；reduced-motion 全局禁用动画；折线图本身无动画。

## 7. 边界与异常态

| 状态 | 呈现 |
|------|------|
| 从未运行过任务 | 整页空态：「暂无统计数据——启动任务后自动记录」 |
| 文件缺失/损坏 | 同空态；不清空、不报错、不尝试修复 |
| 累计有数据但近 7 天全 0 | KPI 与明细照常；图区显示「最近 7 天没有运行」 |
| 今日无记录 | 今日副行 +0；明细「今日」视图全零行置灰 |
| 任务运行中 | 当前模式行高亮 + 清空禁用 |
| 任务崩溃退出 | 保留到最后一次 2s 快照（最多丢 2s） |
| 样本不足 60 秒 | 效率显示「—」 |
| 耗时大数 | 秒数在任务侧存储、前端格式化（d/h/m 自适应），不存格式化串 |
| 数据不足（窗口外） | 固定 7 点补 0，不因无数据日隐藏点位 |
| 切换账号 | 重启生效；成就页顶部「当前角色 · 服务器+角色名（ID：xxx）」标明数据归属 |
| 旧版升级 | 根目录旧统计复制给当前绑定角色；迁移细节见 docs/user-data-layout.md |
