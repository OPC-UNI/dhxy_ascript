# 任务统计报表设计提案（统计页）

> 对应 README 路线图 P2「任务统计报表：完成轮次 / 战斗场次 / 耗时」。
> 设计依据：现有设计系统（docs/ui-redesign.md + design-system/default/MASTER.md）
> 与 UI skill 图表指引（无目标值的 KPI 用统计卡而非仪表盘；<4 个数据点用
> 统计卡而非趋势图；禁止装饰性图表）。

## 1. 目标与范围

- 新增侧边栏入口「统计」，常显（与组号/诊断的条件显隐不同——它是核心页）。
- 三个统计维度：**完成轮次 / 战斗场次 / 耗时**，按 任务模式 分组、按 天 聚合。
- 只做展示 + 清空，不做导出/筛选（后续 P2 延伸另议）。
- 数据累计持久化：跨任务会话、跨天保留（与看板"本次运行"状态严格区分——
  看板读 debug_overlay_state.json 会话级、任务结束即删；统计是历史档案）。

**范围决策（2026-11-08 用户确认）**：
- 入口位置：设置后、系统前。
- 首版只做 **KPI 三卡 + 按任务模式明细表**；最近 7 天趋势图暂不做（§3.3 保留
  为后续增量，实施时跳过）。

## 2. 信息架构

侧边栏顺序（现有：运行 / 任务 / 组号? / 设置 / 系统 / 诊断?）：

```
运行 / 任务 / 组号? / 设置 / 统计 / 系统 / 诊断?
```

- 放在「设置」后「系统」前：位置稳定（不受组号/诊断条件显隐影响）、
  与「系统」同为信息/参考页、使用频率低于任务/设置不抢占前位。
  （备选：紧跟「任务」后——关联性更强但组号显隐会改变其相对位置，不推荐。）
- 入口样式沿用 `.nav-item`：内联 SVG（1.5px 描边、17px）+ 两字文案「统 计」。
  图标用柱状图三竖条（lucide bar-chart 同款 stroke 风格）：
  `<line x1="18" y1="20" x2="18" y2="10"/><line x1="12" y1="20" x2="12" y2="4"/><line x1="6" y1="20" x2="6" y2="14"/>`
- 页面切换复用 `switchPage('stats')`；页面结构复用 `.card` / `.group-title` /
  `.info-row` 体系，全部走既有语义 token（--accent/--gold/--text-dim 等），
  不新增色板。

## 3. 页面设计

```
┌ 统计 ──────────────────────────────────────────────┐
│ ┌ KPI 卡 1 ─┐ ┌ KPI 卡 2 ─┐ ┌ KPI 卡 3 ─┐         │
│ │ 累计轮次   │ │ 累计战斗   │ │ 累计耗时   │         │
│ │ 128       │ │ 347       │ │ 26h 12m   │         │
│ │ 今日 +12  │ │ 今日 +30  │ │ 今日 +2h  │         │
│ └───────────┘ └───────────┘ └───────────┘         │
│ ▸ 本次会话：轮次 +5 · 战斗 +18 · 已运行 41m ●运行中 │  ← 仅运行态出现
├ 按任务模式 ──────────────────── [累计 | 今日] ────┤
│ 模式     轮次    战斗    耗时                       │
│ ▍修罗    48     210    9h 32m        ← 当前运行行   │
│  五倍    30      95    6h 11m                       │
│  五环    18      52    3h 40m                       │
│  仅战斗  —      42     1h 05m                       │
├ 最近 7 天 ─────────────────────────────────────────┤
│ ▂▃▅▃▇▅▂  （轮次=竹青 / 战斗=鎏金 双色柱条）       │
│ 7 天合计：轮次 96 · 战斗 289；最高 11-06（轮次 22）│
├ ──────────────────────────── [清空统计] ───────────┤
└───────────────────────────────────────────────────┘
```

### 3.1 KPI 卡（三张，无仪表盘）

- 图表指引：无目标/基准值 → 用统计卡，不用 gauge/bullet；设计系统明令
  「禁止装饰性图表」。三卡即全部 KPI，**纯数字**。
- 大数字 Consolas（数字字体沿用现状），`今日 +N` 副行 --text-dim；
  数值变化 150ms 过渡（不位移布局）。
- 运行中：卡行下方插入一条「本次会话」摘要条（进度 tint 底 + ●运行中
  chip，复用 phase-chip 动效体系），任务停止后消失。

### 3.2 按任务模式明细表

- 行 = 任务模式（五环/客栈/修罗/五倍/玄枢轶闻/名望/仅战斗），按轮次降序；
  列为 轮次 / 战斗 / 耗时；「仅战斗」轮次列显示「—」（无轮次概念）。
- 右上「累计 | 今日」分段 chip 切换，默认累计。
- 当前运行中的模式行：--progress-tint 底 + 左侧 --accent 竖条（与导航
  active 态同源），跑完即回普通行。
- 数字 + 表头文本双通道（不靠颜色传义，深浅主题都可达 ≥4.5:1）。

### 3.3 最近 7 天趋势（后续增量，本版不做）

- 每天一组双色柱条：轮次（--accent）/ 战斗（--gold），高度按 7 天内
  最大值归一；悬停 title 显示数值，柱上不标数字（密度优先）。
- 纯 div 手绘柱条（离线桌面应用，不引图表库——与现有零依赖 UI 一致）。
- **不足 2 天有数据时不渲染图表**，显示提示「再运行几天后展示趋势」
  （图表指引：<4 数据点用统计卡即可）。
- 图下方一行文字摘要（7 天合计 + 最高日）——图表指引要求 a11y 文本兜底。

### 3.4 操作区

- 「清空统计」link-btn（--danger 悬停态），**二击确认**——沿用删除方案的
  既有模式（再点一次确认 + title 提示变文案），任务运行中禁用（与
  「运行中不可修改」全局语义一致，且防与子进程写文件竞态）。

## 4. 关键交互规格

| 交互 | 规格 |
|------|------|
| 进入统计页 | `switchPage('stats')` 立即刷新一次 |
| 页面内刷新 | 页面激活期间 1.5s 轮询（与看板同节拍）；数据 JSON 签名比对，无变化不重渲染 |
| 离开页面 | 停止轮询（switchPage 钩子内处理） |
| 累计/今日切换 | 即时，无请求（数据一次取回，前端切视图） |
| 清空统计 | 二击确认；运行中禁用；清空后立即刷新为空态 |
| 数值更新 | 150–200ms 过渡；`prefers-reduced-motion` 下直跳 |
| 键盘 | 全部可 Tab 到达，focus-visible 2px accent outline（全局已有） |

## 5. 后端数据通道（唯一后端新增）

### 5.1 数据模型：task_stats.json

- 新文件 `task_stats.json`，与 config.json / debug_overlay_state.json 同目录。
  **与状态文件分家**：状态文件会话级、shutdown 删除、含绘制指令；
  统计文件是历史档案，永久保留。
- **单写者 = 任务子进程**（复用 debug_overlay._supervise 既有 2s 周期，
  同一循环内原子写入；shutdown() 里删状态文件前先终写一次统计）。
  主进程只读——天然无并发写。
- 结构：

```json
{
  "total": {"rounds": 128, "battles": 347, "seconds": 94320,
            "modes": {"修罗": {"rounds": 48, "battles": 210, "seconds": 34320},
                     "五倍": {"rounds": 30, "battles": 95,  "seconds": 22260}}},
  "daily": {"2026-11-06": {"rounds": 22, "battles": 65, "seconds": 19800}},
  "session": {"started_at": 1762600000, "rounds": 5, "battles": 18,
              "seconds": 2460, "mode": "修罗"}
}
```

- `daily` 滚动保留最近 90 天（写时修剪），防文件无限增长。

### 5.2 打点（全部在任务子进程内，不新增协议通道）

| 指标 | 打点方式 | 改动点 |
|------|----------|--------|
| 轮次 | 新增 `debug_overlay.record_round()`：计数 +1，归当前 _task 模式 | 5 个既有 `set_progress(f"{done}/{total}")` 调用点旁各加一行（kezhan/wubei/wuhuan/xiuluo/xuanshu——恰为每轮完成点，不解析字符串、无新埋点） |
| 战斗 | 复用既有 `set_battle(no)`（每场进入必调）：supervisor 每周期对比上次 battle_no 求增量，归当前模式 | 零改动（2s 粒度足够报表用） |
| 耗时 | supervisor 每周期把 tick 增量归当前模式 + 当日；会话开始时间由 `main.task_start` 置 `set_session_start()` | main.py 一行 + debug_overlay 计数 |

**与调试开关的关系**：统计 tick 在 `debug_overlay._supervise` 内执行，
与「调试信息」开关无关——开关只控制悬浮层绘制指令与绘制子进程，关闭
时统计照常累计（见 docs/performance.md §11 实测）。

### 5.3 桥接接口（control_window.py）

| 接口 | 行为 |
|------|------|
| `get_task_stats()` | 读 task_stats.json → 返回 {total, modes, daily(最近7天), session_live?}；文件缺失/损坏返回空结构 |
| `clear_task_stats()` | 任务运行中拒绝（返回 error）；否则清空文件，返回 success |

## 6. 视觉沿用（不新建设计系统）

- 全部沿用 ui-redesign §7 语义 token 与 MASTER.md（深色墨色/浅色宣纸双主题
  自动适配）；柱条色 = --accent（竹青·轮次）与 --gold（鎏金·战斗）。
- 图标：内联 SVG 1.5px 描边，禁 emoji；圆角卡 8px；间距 4/8px 节奏，
  页面 padding 14px（高密度仪表盘档）。
- 动效 Subtle 档：过渡 150–200ms，运行态 pulse 2s，reduced-motion 全禁。

## 7. 边界与异常态

| 状态 | 呈现 |
|------|------|
| 从未运行过任务 | 空态：「暂无统计数据——启动任务后自动记录」（--text-dim） |
| 文件缺失/损坏 | 同空态；不清空、不报错、不尝试修复 |
| 任务运行中 | KPI 下方「本次会话」条 + 明细表当前模式行高亮 + 清空禁用 |
| 任务崩溃退出 | 统计保留到最后一次 2s 快照（最多丢 2s），会话条消失 |
| 任务停止后 | 状态文件被删不影响统计文件；统计页数据照常可读 |
| 数据不足（趋势图） | 有数据的日期 <2 天 → 不渲染图表，显示提示文案 |
| 耗时大数 | 秒数在任务侧存储、前端格式化（d/h/m 自适应），不存格式化串 |

## 8. 实施步骤建议

1. **后端打点与持久化**：debug_overlay 加 record_round/set_session_start
   + _supervise 循环内写 task_stats.json + shutdown 终写（含 90 天修剪）；
   5 个任务模块 set_progress 旁加 record_round。
2. **桥接**：control_window 加 get_task_stats / clear_task_stats。
3. **页面骨架**：侧边栏「统计」入口 + page-stats 容器 + switchPage 接入
   + 1.5s 轮询与签名比对。
4. **渲染**：KPI 三卡 → 明细表（累计/今日切换）→ 7 天趋势（含空态门）。
5. **收尾**：清空二击确认、运行态高亮、reduced-motion 检查；
   README 路线图 P2 行状态更新 + 功能列表同步（项目约定）。
